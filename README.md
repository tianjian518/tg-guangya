# TG 频道磁力 → 光鸭云盘 自动转存

> 当前版本：**v1.1.0** ｜ 开源协议：MIT ｜ Docker 镜像：`tianjian518/tg-guangya`

把 Telegram 公开频道里发的磁力链接，自动丢给光鸭云盘**离线下载**（光鸭服务器自己跑 BT，不占你带宽）。

## 能干啥

- 监听你订阅的 TG 频道，自动抓取磁力链接
- 去重（同一个资源不重复提交）
- **自动分类转存**：按「内容形态 + 地区」自动建子目录（华语电影 / 欧美电影 / 国产剧 / 日韩剧 / 日本动漫 …），
  资源各归各位，不用手动整理
- 关键词 / 画质过滤（比如只转 1080P 以上的）
- **洗版 / 版本升级**：盘里已有同名同集文件、新链接质量更优时，自动替换旧版本
- **监控历史**：面板可回看每条资源的处理结果（转存 / 跳过 / 洗版 / 失败）与原因
- 提交到光鸭离线下载，完成后通知你
- **TG 机器人遥控**：手机上直接发磁力就转存，`/status` 查进度、`/pause` 暂停、`/add 频道` 加频道
- 全程只用**网页抓取公开频道**，不碰 Telegram 账号、零风控（默认模式）

## 三个真相（先看这个）

1. **光鸭有原生离线下载接口，磁力直接支持**——所以"下 BT 再上传"那套根本不需要，程序只发个链接过去就完事。
2. **你订阅的影视频道基本都是公开的**，公开频道有网页版 `t.me/s/频道名`，不用登录、不用申请 API、不会被封。这就是默认模式。
3. **"Userbot"不是机器人**。那是拿你账号登录的第三个客户端（和装第二个 TG 桌面端没区别），能看到你账号里所有频道。默认不用它；只有你要监听**私有频道**或要**秒级实时**才切过去，且建议用小号。

## 怎么跑

```bash
# 1. 装依赖
pip install -r requirements.txt

# 2. 准备配置：复制示例，填你的频道名
cp config.example.yaml config.yaml
#   编辑 config.yaml：sources.channels 填频道用户名

# 3. 首次扫码登录光鸭（令牌自动写回 config.yaml）
python login.py

# 4. 启动（默认网页抓取模式，常驻运行）
python main.py --config config.yaml
```

## TG 机器人（手机上遥控，可选）

面板开着只能在电脑前点，装了机器人之后**躺床上也能管**：直接把磁力链接发给机器人，
它立刻走和频道抓取完全相同的流程（过滤 → 去重 → 自动分类 → 洗版 → 提交）。

### 三步开起来

1. Telegram 里找 **@BotFather**，发 `/newbot`，按提示拿到 token（形如 `123456:ABC-DEF…`）
2. 找 **@userinfobot** 发句话，拿到你自己的**数字 ID**
3. 面板 → 系统设置 → **TG 机器人**，填进去保存 → **重启监听**（概览页：停止监听 → 启动监听）

也可以直接改 `config.yaml`：

```yaml
bot:
  enabled: true
  token: "123456:ABC-DEF..."
  admin_ids: [123456789]     # 你的数字 ID，多个用逗号分隔
  notify: true               # 转存结果推送给你
  proxy: ""                  # 留空则沿用 sources.proxy
  allow_anyone: false        # true = 谁都能用（不建议）
```

> 机器人依赖 `pyTelegramBotAPI`，`pip install -r requirements.txt` 已包含。
> 没装也不影响原有功能——未启用时压根不会 import 它。

### 能用的命令

| 输入 | 作用 |
|---|---|
| 直接发磁力 / 迅雷 / 电驴 / http 直链 | 立即提交光鸭离线下载 |
| `/status` | 查离线任务进度（进行中 / 完成 / 失败，带百分比和大小） |
| `/stats` | 转存统计（成功、失败、跳过各多少） |
| `/pause` `/resume` | 暂停 / 恢复频道轮询 |
| `/channels` | 列出当前监听的频道 |
| `/add 频道名` `/del 频道名` | 增删频道（写回配置文件，长期生效，不用重启） |
| `/find 关键词` | 在监控历史里搜资源 |
| `/id` | 查你自己的数字 ID（填 admin_ids 用） |
| `/help` | 帮助 |

### 几个注意点

- **没填 admin_ids 时谁都用不了**（机器人会提示你 ID）——这是防陌生人乱用的保护，不是故障。
- `/add` 加频道后，新消息要等**下个轮询周期**才会被抓到，不会立刻出结果。
- 机器人**走的还是网页抓取那套**，不需要你的 Telegram 账号，零风控；
  它只是多了个"你主动下命令"的入口，和 userbot 模式（拿账号实时监听）两码事。
- 网络不通或 token 填错时，机器人线程会自己重试，**不会拖垮主程序**，日志里能看到重连提示。

## 数据持久化（存储卷）

所有会变动的用户数据都收敛到一个**数据目录**，不在代码目录里写文件，方便整体备份和容器化部署：

| 数据 | 文件 | 说明 |
|---|---|---|
| 配置 | `config.yaml` | 账号令牌、频道列表、过滤/运行参数 |
| 去重库 | `tg_guangya.db` | 已提交磁力的记录（避免重复转存） |
| 会话 | `tg_user.session` | 仅 userbot 模式产生（Telegram 登录态） |

数据目录的解析优先级：

1. 环境变量 `DATA_DIR`（显式指定，最高优先）
2. 容器挂载点 `/data`（存在即用）
3. 当前目录已有 `config.yaml`（兼容旧版本地部署）
4. 否则在当前目录新建 `./data`

> 本地直接跑：首次会新建 `./data/`，把配置和库放进去；旧版把 `config.yaml` 放仓库根目录的仍兼容，沿用原目录。
> 容器部署：把宿主机目录挂到 `/data`，重建/升级容器数据不丢。

## 备份与还原（仿 OpenList）

在「系统设置 → 备份与还原」里：

- **导出备份**：把 `config.yaml` + 去重库 + 会话文件打包成 `.zip` 下载到本地（含 `backup_manifest.json` 记录版本与时间）。
- **导入还原**：选一个备份 `.zip` 覆盖当前数据。还原前系统会自动把现有数据存成 `.bak`；还原会重启监听（若正在运行）。

备份接口：`GET /api/backup/download`、`GET /api/backup/info`、`POST /api/backup/restore`（multipart 上传）。还原做了校验：zip 必须含 `config.yaml` 且能正常解析，只允许落地配置/库/会话三类文件，拒绝任何路径穿越。

## 配置要点（config.yaml）

| 项 | 说明 |
|---|---|
| `sources.channels` | 公开频道用户名，去掉 `@` 和 `t.me/` |
| `sources.type` | `web`（默认，无需登录）或 `userbot`（需 Telegram api_id/api_hash） |
| `sources.poll_interval` | 网页轮询间隔，秒，最小 30 |
| `filter.include_keywords` | 命中任意一条才转，留空=全转 |
| `filter.exclude_keywords` | 命中任意一条跳过 |
| `filter.min_resolution` | 最低画质：`1080P` / `2160P` / `4K` |
| `output.parent_id` | 光鸭目标目录 fileId，留空存根目录（建议建个专门目录） |

## 配频道（重点）

抓取器会识别频道消息里的 **磁力 `magnet:`、迅雷 `thunder://`、电驴 `ed2k://`** 三类链接
（光鸭离线下载都支持），所以发这几种链接的频道都能用。已内置一批影视频道到
`config.yaml` 和 `seeds/channels_seed.txt`。

- **手动加**：直接往 `sources.channels` 里加用户名即可；
- **不想逐个加**：把频道丢进 `seeds/channels_seed.txt`（一行一个）。

> 提示：频道是否真能抓到，取决于它是否为**公开频道**且没被封。抓不到的频道会被
> 自动跳过，不影响运行。已内置的 28 个频道是从公开清单里挑的、相对活跃的电影/网盘分享频道，
> 个别可能失效，删掉即可。

## 自动发现频道（可选）

想让频道库"越跑越全"，打开 `discovery.enabled: true`：

```yaml
discovery:
  enabled: true
  interval_hours: 24
  seed_file: "seeds/channels_seed.txt"
  seed_urls:
    - "https://raw.githubusercontent.com/zhan2046/telegram-groups/main/README.md"
```

开启后，主程序会起一个**后台线程**，每隔 `interval_hours` 小时从 `seed_file` 和
`seed_urls` 里抠出新的频道用户名，去重后自动追加进 `config.yaml` 的 `sources.channels`，
网页抓取器随即开始监听新频道。

也可单独跑一次性发现，验证效果：

```bash
python discover.py --config config.yaml          # 扫描并打印发现的新频道
python discover.py --config config.yaml --save   # 发现后直接写入配置
python discover.py --text "关注 @abc @xyz t.me/foo"   # 从一段文本里抠频道
```

### 候选频道验证（verify_channels）

发现机制只负责"加频道"，并不验证"这频道到底发不发磁力"。网盘分享类频道（只发夸克/天翼链接）加进去只会空转。
`verify_channels.py` 直接用公开网页 `t.me/s/<频道>` 扫描最近几页消息、统计磁力数，帮你把"真有产出"的频道筛出来：

```bash
# 验证种子文件里「候选待验证」区段标注的频道
python verify_channels.py --seed seeds/channels_seed.txt

# 只输出值得保留的频道清单（可直接粘进 sources.channels）
python verify_channels.py --channels hdhhd21 zhenyingsg xingqiump4 --keep
```

无需 Telegram 账号、无需登录即可运行（纯公开网页抓取）。

## 自动分类转存（默认开启）

默认情况下所有资源会平铺堆在转存目录里，找起来很痛苦。开启自动分类后，程序会先判定
资源的**内容形态**和**地区**，再**自动在转存目录下建好对应子目录**并把资源转存进去。

### 分类依据

参考主流媒体库实践（NASTool / Emby / Jellyfin 中文社区、飞牛与极空间用户习惯）：
按「内容形态 + 地区」两个维度划分，网盘场景普遍采用扁平化的「地区 + 类型」命名。

| 内容形态 | 判定信号 |
|---|---|
| 电影 | 年份 + 发行格式（1080P / BluRay / REMUX …） |
| 剧集 | `S01`、`第01集`、全集、更新至、网剧、美剧/韩剧… |
| 动漫 | 动漫 / 动画 / 剧场版 / 新番 + 一批高频番名 |
| 纪录片 | 纪录片、BBC、NHK、国家地理、探索频道 |
| 综艺 | 综艺 / 真人秀 + **`第X期`**（综艺标志性说法，剧集用「第X集」） |
| 演唱会 | 演唱会 / 音乐会 / 音乐节 / Concert |

| 地区 | 判定信号 |
|---|---|
| 华语 | 国语、普通话、中字、简体、国产、**粤语、繁体、TVB、港剧、台剧（港台统一并入华语）** |
| 日韩 | 日语、韩语、日剧、韩剧、JPN / KOR |
| 欧美 | 英语、美剧、英剧、欧美、English |
| 其他 | 泰语、印度、越南、新加坡… |

> 注：港台地区不单独设类，粤语/香港/台湾/ TVB 等内容统一归入华语目录（如「港台电影」→「华语电影」、「港台剧」→「国产剧」）。

**默认目录对照表**（扁平结构）：华语电影、欧美电影、日韩电影、其他电影、
国产剧、欧美剧、日韩剧、其他剧集、国产动漫、日本动漫、欧美动漫、
纪录片、综艺、演唱会。

### 目录结构可选

- `flat`（默认，推荐）：`转存目录/华语电影`、`转存目录/国产剧`
- `two_level`：`转存目录/电影/华语`、`转存目录/电视剧/欧美`
  （纪录片 / 综艺 / 演唱会 不区分地区，只建一级）

### 判不准怎么办

判定采用**打分制 + 兜底**，每条都会记录命中信号与置信度。语言标签齐全的标题基本 100% 命中；
无标签时按中文占比推断（全中文→华语，全英文→欧美），实在判不出就进 `未分类` 目录
（可在设置里改名）。**判错也不会丢资源**——最差落在兜底目录里。

目录不存在会自动创建（`create_missing`），已存在则复用，不会重复建；
建目录失败会降级回已解析层级，**不会因此丢弃磁力**。

### 配置

```yaml
organize:
  enabled: true
  structure: flat            # flat | two_level
  create_missing: true       # 目录不存在时自动创建
  unknown_dir: 未分类         # 判不出类别时的归属
  mapping:                   # 自定义目录名，格式 "内容形态:地区": 目录名
    "movie:cn": 华语电影
    "tv:cn": 国产剧
    "anime:jpkr": 日本动漫
```

面板「系统设置 → 自动分类」里有**分类试算**：粘贴一条频道标题，立刻看到它会被分到哪个目录、
命中了哪些词、置信度多少——改配置时可以先试后存。

## 转存去重（防重复转存，默认开启）

同一部影视常被不同频道以**不同磁力**反复发布，只靠磁力 hash 去重会失效——同片不同磁，照样被转存七八上十次。
本程序做**两级去重**，先查本地、再查云端：

1. **本地记录去重**：按磁力 btih 去重，同一链接再次出现直接跳过（快、零网络）。
2. **云端复查**：在资源对应的分类目录里，按**片名**匹配光鸭盘里有没有这个片子
   - 云端已有 → **丢弃**（用户保留着，或是不同磁力指向同一部）
   - 云端没有（被你删了）→ **重新转存一次**

> 光鸭没有「全局搜索」接口，云端查重只能「在分类目录下列举文件名、按片名匹配」。
> 片名匹配会剥离年份、分辨率、编码、语言、剧集进度等噪声，只比对核心片名，
> 并做了续集区分（「流浪地球」不会误判成「流浪地球2」）、中英混合标题（「奥本海默」能命中 `Oppenheimer`）。

去重逻辑在 `core/dedup.py`（`CloudDedup`），目录列表带缓存（默认 300 秒）避免频道刷屏时反复列举。

### 配置

```yaml
dedup:
  cloud_check_new: true    # 首次出现的链接也去云端复查（防不同磁力重复转存）。关掉则只做本地 hash 去重
  cache_ttl: 300           # 云端目录列表缓存秒数，最小 30
```

面板「系统设置 → 运行参数 → 转存去重」里可实时开关与调缓存。

### 追剧 / 追番（不同集互不误杀）

一部剧会分多集陆续发布，每一集都是**不同的磁力链接（不同 btih）**。去重时如果只比对核心片名，
「第6集」会被剥成和「第5集」一样的名字，从而被误判成「盘里已有 → 丢弃」，新剧集就这么被误杀了。

解决办法：**集数感知**。先把标题里的集数归一化成统一签名——
`第6集` / `S01E06` / `EP06` / `第2季第3集` 都归一成 `s01e06` / `s02e03` 这种形式，再按规则比对：

- 两方都带集数签名且**不同** → 视为不同集（第6集不会被第5集误杀，照常转存进同一分类目录）
- 两方集数签名**相同**（或有一方没标集数，如整剧包「全30集」、未单独标集的电影）→ 才继续比对核心片名

效果：

| 场景 | 云端已有 | 新链接 | 结果 |
| --- | --- | --- | --- |
| 追剧：第6集新链接 | 第1~5集 | 第6集（新磁力） | **转存**（不误杀） |
| 同集重复发布 | 第5集 | 第5集（换了个磁力） | 丢弃（去重仍生效） |
| 集数格式不同 | `S01E06` | `第6集` | 丢弃（识别为同一集） |

> 集数抽取与匹配逻辑见 `core/dedup.py` 的 `episode_sig()` 与 `names_match()`。

### 洗版 / 版本升级（可选，默认关闭）

同一部片常被不同人发布成不同质量（1080P / 4K / REMUX / Atmos …）。开启洗版后，当盘里已有同名同集文件、但新链接质量**更优**时，自动**删除旧版本并转存新版本**；质量相同或更差则照常跳过。

质量由 `quality_score()` 综合评分：分辨率（4K=120 / 1080P=60 / 720P=35）为主，外加 编码（HEVC/REMUX +15）、音轨（Atmos/DTS-HD/TrueHD +10）、HDR/DV（+8）、10bit（+4）。新分 > 旧分即触发替换。

| 场景 | 盘里已有 | 新链接 | 结果（洗版开） |
| --- | --- | --- | --- |
| 4K 覆盖 1080P | `流浪地球2 1080p` | `流浪地球2 4K` | **洗版**：删旧、转新 |
| 不降级 | `流浪地球2 4K` | `流浪地球2 1080p` | 跳过（不降级） |
| 同质量 | `流浪地球2 1080p` | `流浪地球2 1080p 国语` | 跳过（无更优） |

> ⚠️ 删除为**不可逆**操作。默认关闭；在「系统设置 → 运行参数 → 转存去重」里勾选「版本升级」开启。
> 删除走光鸭 `/userres/v1/file/delete`；逻辑见 `core/dedup.py` 的 `quality_score()` 与 `CloudDedup._decide_upgrade()`。

### 监控历史

面板「🗂️ 监控历史」页记录频道里每一条被命中的资源、处理结果（转存 submitted / 洗版 upgraded / 跳过 skipped / 失败 failed）与原因、频道、分类、时间，可按状态筛选。

数据来自去重库 `magnets` 表（每条磁力一条记录，含标题 / 状态 / 任务号 / 分类）。接口 `GET /api/history?limit=&status=`，序列化见 `web/server.py` 的 `_record_to_dict()`。

## 切到 userbot 模式（可选）

只有要监听私有频道或要实时推送时才用。步骤：
1. 去 https://my.telegram.org 申请 `api_id` / `api_hash`，填进 `telegram:` 段
2. `sources.type` 改为 `userbot`
3. 首次运行会要你输入手机号 + 验证码登录。**建议用闲置小号**，低频、只监听不发言

## 技术说明

- 光鸭没有公开 API 文档，接口依据 [LitePan](https://github.com/Ponphil/LitePan)（PolyForm Noncommercial 许可）对光鸭驱动的逆向实现编写
- 关键接口：`account.guangyapan.com/v1/auth/device/code`（扫码）、`/v1/auth/token`（刷新）、`api.guangyapan.com/cloudcollection/v1/{resolve_res,create_task,list_task,delete_task}`
- 目录接口（自动分类用）：`POST /userres/v1/file/get_file_list`（列目录）、`POST /userres/v1/file/create_dir`（建目录，body `{parentId, dirName}`）
- access_token 有效期 2 小时，靠 refresh_token 自动续期，长期可跑

## 合规提醒

磁力是中性技术，但频道里的影视资源多涉及版权。**自用转存**与**对外分发**是两回事，请只用于个人存储，勿二次传播。

## 容器部署（Docker / 群晖 / 各类面板）

```bash
# 构建并后台启动
docker compose up -d

# 访问面板
# http://<你的服务器IP>:8000
```

- 数据卷：宿主机的 `./data` 挂载到容器 `/data`，配置/库/会话全在里面，容器删了也不丢。
- 升级：`docker compose down && docker compose up -d --build`，数据目录不变。
- 想换数据位置：改 `docker-compose.yml` 里 `- ./data:/data` 的左边路径，或加环境变量 `DATA_DIR`。
- 首次进入面板，去「系统设置 → 光鸭账号」扫码登录；「转存目录」选个目标文件夹即可开始工作。

单容器裸跑也可以：

```bash
docker run -d --name tg-guangya \
  -p 8000:8000 \
  -v /opt/tg-guangya-data:/data \
  -e DATA_DIR=/data \
  tianjian518/tg-guangya:latest
```

> 也可直接从 Docker Hub 拉镜像：`docker pull tianjian518/tg-guangya:latest`。
> 镜像由 GitHub Actions 在每次推送到 `main` 或打 `v*.*.*` tag 时自动构建并推送（见 `.github/workflows/docker.yml`），
> 同时构建 **amd64 / arm64** 双架构（树莓派、群晖 ARM、飞牛、Apple Silicon 等均可直接 `docker pull`），
> 需要仓库 Secrets 配置 `DOCKERHUB_USERNAME` 与 `DOCKERHUB_TOKEN`。
